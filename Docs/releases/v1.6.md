## Summary
- Be Kind milestone: assist talkthroughs plus repair of the defects that
  silently punish players. (In progress — see `.planning/v1.6-BRIEF.md`.)
- Nonogram interaction reliability patch.
- Polished native launch and branded app-entry experience.

## User-facing changes
- Launch now opens with the GameDrawer mark on a matching native and in-app brand frame, then transitions directly into onboarding or The Drawer without flashing the wrong destination.
- GameDrawer now uses the 9A.2 Video drawer app icon across light, dark, and tinted appearances.
- Nonogram now previews the targeted cell and highlights its row/column hints while the finger is down. Players can slide to correct an adjacent-cell miss before lifting to commit, making 20×20 boards safer in Lives mode.
- The Nonogram grid now uses 85% of its available width instead of 78%, giving every cell a larger physical target—most noticeably on 20×20 puzzles.
- Horizontal Nonogram clues now use explicit centered-dot boundaries (`1·5·11`) so adjacent clues cannot be mistaken for one multi-digit number; the hint rail remains the same size.
- Nonogram clue cross-offs now preserve puzzle information: unique completed run lengths still cross immediately, while repeated values wait for visible progress anchored from either edge.
- Fast Nonogram swipes fill the complete path immediately instead of visibly trailing behind the finger.

## Internal changes
- `AppStartupController` gained `reconfigure(cloudSyncEnabled:)`, which rebuilds the `ModelContainer` against a new sync mode in place. `cloudSyncEnabled` changed from a `let` captured at init to a `private(set) var`, and a `containerToken` now keys the destination subtree in `AppEntryRootView` so a swapped container rebuilds the tree instead of leaving `@Query` views bound to the retired `ModelContext`. Both modes open the same on-disk store (D-08 same-store-path), so no local row is created, moved, or deleted — only CloudKit mirroring changes. The controller is injected through a new `\.appStartupController` environment key, matching the existing `AuthStore` seam.
- Deleted `AuthStore.shouldShowRestartPrompt` and the root-level "Quit and reopen to finish iCloud setup" alert in `RootTabView` (D-03/D-04/D-05). Both existed only to work around the sync mode being fixed at launch; with live reconfiguration there is nothing left for the user to do by hand.
- Moved SwiftData container preparation behind an observable startup controller, with delayed progress feedback, debug launch-path seams, and focused state/UI coverage.
- Added regression coverage for swipe activation thresholds, horizontal/vertical path interpolation, row-hint display/accessibility grammar, and nuanced clue cross-off behavior.
- Added a UI regression test that reproduces the post-transfer Keychain/UserDefaults desync (sync flag on, no stored Apple userID) and asserts the account-management rows stay reachable.
- Repointed all repo paths from the dead `~/Desktop/<Repo>` layout to `~/Developer/<Repo>` (WRAPUP.md, CLAUDE.md, `tools/nonogram/finalize.py`). The wrap-up website step was an `&&` chain starting with `cd` into a missing directory, so it short-circuited and no-oped silently; it is now separate statements behind an explicit failure guard.
- Widened the pre-commit token-discipline hook from `Games/` and `Screens/` to also cover `Core/` and `App/`, matching CLAUDE.md §1, which states the no-hardcoded-colors rule with no directory carve-out. Only newly added lines are inspected, so existing code is unaffected. `Core/GameKitClassic.swift`, `Core/GameKind+AccentColor.swift`, and `Core/SurfaceDepth.swift` carry a documented Color-only exemption because they define the raw colors the rest of the app consumes through tokens; the radii and spacing checks still apply to them.
- Collapsed `AGENTS.md` into a git symlink to `CLAUDE.md`, making agent-rule drift structurally impossible. The two files had been hand-maintained mirrors and had already diverged — AGENTS.md still declared "MVP scope: Minesweeper only" after v1.5 shipped with Stack and Snake. Content unique to AGENTS.md and still true was folded into CLAUDE.md first, including a new §0.5 Commands section (CLAUDE.md previously documented no build command at all).
- Added `Core/AppLog.swift`, a central `os.Logger` namespace (app, audio, auth, sync, storage, puzzles, haptics), mirroring the `AppLog` pattern in FitnessTracker. `NonogramLibrary` and `SFXPlayer` now log through it instead of `print()` and inline `Logger(subsystem:category:)` construction; the Nonogram calls also lose their `#if DEBUG` guards, since `os.Logger` is compiled out of the hot path when not collected. Recorded as CLAUDE.md §8.17, with a documented carve-out for the dev-only seeders (`ScreenshotSeeder`, `DummyDataSeeder`, `AppStartupController`) whose output is meant for a human watching Xcode's console.
- Pre-commit hook hardened: added a `print()`/`debugPrint()` check honoring the §8.17 tooling carve-out, added a line-level `// token-exempt: <reason>` escape hatch matching FitnessTracker's hook (a bare `// token-exempt` with no reason does not suppress), widened the Finder-dupe pattern from ` 2.swift` to any ` <n>.swift`, and replaced the filename loop with NUL-delimited iteration — the previous `for f in $staged` word-split on paths containing spaces, which is exactly the Finder-dupe case the first check exists to catch.

## Fixes
- Turning on iCloud sync now takes effect immediately instead of asking the user to quit and reopen the app. The container's sync mode was decided once at launch, so signing in only wrote a flag — anyone who dismissed the restart prompt (or simply did not force-quit) kept using a local-only store while their iCloud stats sat untouched. This was the whole first-run restore experience on a new device, not an edge case. Signing out, account deletion, and silent credential revocation now drop the container back to local-only in the same session too, so writes after sign-out no longer reach the account just left.
- Replaced the startup-time SwiftData fatal error with a data-safe retry screen when the persistent container cannot open.
- Removed the cell-edge sample rejection that delayed fast-swipe interpolation.
- Unified tap targeting and swipe-to-fill under one board gesture: short touches commit the previewed cell on lift, while longer axis-locked movement becomes a smear.
- Expanded the grid while retaining the existing hint strips; a broader hint-layout redesign remains intentionally out of scope for this patch.
- Settings → SYNC now keeps Sign out and Delete account reachable whenever iCloud sync is actually running, not only when a Keychain sign-in record exists. The developer-team transfer changes the App ID prefix, which orphans that Keychain record on update while the sync flag survives — previously that combination hid both controls while stats kept syncing.
- A Sign in with Apple credential state of `.notFound` no longer signs the user out. `.revoked` and `.transferred` still do — both are positive server statements, and `.transferred` is what the developer-team transfer produces. An unrecognized future state now also preserves the session. The argument is the asymmetry, not a reproduction: `.notFound` is ambiguous between "no credential exists" and "not visible right now", and only the first reading justifies destroying one. Keeping a stale credential costs nothing here (the user can sign out from Settings, a real `.revoked` resolves it on the next probe, and iCloud sync is gated on `cloudSyncEnabled` rather than on the credential); discarding a valid one silently flips the UI to signed-out.
- A `credentialRevokedNotification` arriving within 5 seconds of a successful sign-in is now ignored, on the reported behavior that Apple posts it on some successful authorizations. Outside that window a revocation is honored unconditionally — revoking access from Settings -> Apple Account must still sign the user out — and `validateOnSceneActive()` still acts on a `.revoked` probe with no grace period, so the guard has a backstop within one scene activation. `AuthStore` takes an injected clock so both sides of the boundary are tested without sleeping.
- **Both of the two entries above are unverified hardening, not reproduced fixes.** Neither behavior was observed in GameKit; both were ported after auditing FitnessTracker's auth path. The one live observation behind them — a `credentialState` probe returning `.revoked` moments after a successful sign-in — came from the FitnessTracker *simulator*, where Sign in with Apple credential state is not trustworthy, and it was a probe result rather than the notification the 5-second window guards. An earlier draft of this log and of commit 28faa4d cited that observation as direct evidence for the notification path; it is not, and that claim is withdrawn here. The `Ignoring credentialRevokedNotification` log line is the instrument: if it never fires on a real device, this guard is inert and should be deleted rather than kept on faith.
- The SYNC status row no longer reports "Synced just now" off a CloudKit `.setup` event. `.setup` only means CloudKit reached the container; no record has moved in either direction, and on a fresh install it fires before any import — so a restore that pulled nothing still read as a healthy one. The row now stays on "Syncing…" until an `.import` or `.export` actually completes. Setup *failures* still surface as "iCloud unavailable". Found while diagnosing the same defect in FitnessTracker's sync pill.

## Risks / notes
- The native launch frame uses a fixed brand background because UIKit renders it before DesignKit and the saved user theme are available; the app crossfades from that frame into the resolved theme.
- The selected icon intentionally uses one unified full-color master across all three iOS appearance slots.
- Build 2 uploaded with warning ITMS-90076 (potential loss of Keychain access): the developer-team transfer moved the App ID prefix from JCWX4BK8GW to ATRCA5V7ZV. The warning is informational and unfixable in the binary — the old prefix cannot be reclaimed. Only the stored Sign in with Apple userID is affected; local stats, the iCloud sync flag, and the CloudKit container are untouched, so sync continues across the update and affected users simply re-sign-in. Apple's transfer_sub user-migration endpoint (TN3159) is not needed here because the userID is not used as a data key.
- Nonogram swipe activation now requires 24–32pt of initial travel, leaving room to correct an adjacent target before touch-up; interpolation still backfills every cell crossed before activation.
