## Summary
- Be Kind milestone: assist talkthroughs plus repair of the defects that
  silently punish players. (In progress — see `.planning/v1.6-BRIEF.md`.)
- Nonogram interaction reliability patch.
- Polished native launch and branded app-entry experience.

## User-facing changes
- Help is now visible from a lightbulb on every supported game screen instead
  of being discoverable only through Settings or an overflow menu. Video Mode
  keeps the action in its existing menu to protect compact play layouts.
- Hints now share one calm coach card with plain instructions and a direct
  next action. Nonogram marks each suggested square as Fill or X and keeps the
  remaining actions visible until they are completed.
- Nonogram and Sudoku now offer Keep Solving after the last life. The original
  loss and time stay recorded, while the current board continues in a
  no-penalty Practice state without creating a second result.
- Five Letter can suggest a useful accepted guess that is never one of the
  possible answers; FreeCell highlights the exact source and destination of a
  productive legal move; Word Grid labels its assist as Reveal a word.
- Minesweeper can now talk you through a safe square. "Show me a step" finds one that can be proved safe and explains the argument — either counting a single number ("this 2 already touches both its mines, so the rest are safe") or comparing two overlapping numbers, which is the pattern most players never quite articulate. The numbers carrying the argument are outlined alongside the square being recommended, so you can check the reasoning instead of taking it on trust. Flags are ignored entirely when working it out, so a wrongly flagged square cannot lead the hint astray. When neither rule can prove anything, it says so honestly rather than guessing on your behalf — and offers to open a genuinely safe square for you, which reads the real board rather than the reasoning, so it cannot go wrong.
- FreeCell can show you a move. It suggests one worth making rather than merely legal — there is nearly always something legal to do in FreeCell and most of it is shuffling. Banking a card to a foundation comes first, but only when nothing still needs it as a landing spot, so a hint can never turn a winnable deal into a lost one. Then getting a card back out of a free cell, then a move that empties a column. Parking a card in a free cell is offered last and says so, because that is the move most likely to cost you the deal. It names the card rather than the column number, so you can find it by looking instead of counting.
- Word Grid can find you a word. "Find me a word" outlines one that is still on the board, shortest first, so you can see the shape of a legal path rather than being told an answer you then have to locate. A revealed word scores 0 — you get unstuck, and the score stays a record of what you spotted yourself. It never reports how many words remain, because the board is built from a smaller word list than it accepts, so any total would be wrong.
- Five Letter can tell you how many answers still fit. "How many words fit?" counts the answers consistent with every clue you have been shown — "142 answers still fit your clues", down to "only one answer still fits". It gives away nothing that is not already on your board in green, yellow, and grey; it only answers whether you are actually close. That is deliberately the whole assist: in a five-letter puzzle a revealed letter is a fifth of the answer, so there is no honest middle ground between saying nothing and solving it.
- Losing a Minesweeper board no longer throws it away. "Try this board again" is now the main button on the end card, and it deals the same mines so you can see how it should have gone. The button that gives you a fresh layout is now called "New board" — it used to say "Restart", which read as "play this again" but silently dealt a different board. It is not a second chance: the loss is already recorded and the run is over. A replayed win counts as a game played but never sets a best time — losing has already shown you every mine, so the time is not comparable to a first solve. It is also not reported as a hinted game, because no hint was used. The other games already kept your board on a loss; Minesweeper was the one that did not.
- Hints now point at the squares they are describing. Previously the wording referred to "these squares" while nothing on screen showed which, so the advice was hard to act on. Nonogram now outlines the squares it has worked out and accents the clue numbers for that row or column, and names the position in words ("squares 3 to 8"). Sudoku rings the square it is talking about and shades the row, column, or box that proves it, and the sentence refers to the ring rather than making you find coordinates.
- Sudoku can now talk you through the next digit. "Show me a step" finds a square you can prove and explains the argument — either that a square has only one digit left, or that in a given row, column, or box one digit fits in only one place. It stops there. Asking a second time gives the answer, and a third tap fills it in, so the default is a nudge rather than a solution. The whole sequence counts as one hint, not three. If a digit already on the board is wrong, it says so and declines rather than reasoning from a false premise, and when a puzzle needs a technique harder than these it admits that plainly instead of inventing a step.
- Nonogram can now talk you through the next square. "Show me a step" in the toolbar menu finds a square you can prove and explains the reasoning in a sentence — for example, that a run of 8 in a 10-wide row covers the middle 6 wherever it sits. It teaches the argument rather than handing over the answer, so the same reasoning works the next time you meet it. When no single row or column can be worked out, it says so plainly instead of inventing a step, and if something already placed contradicts its clues it points you at the red lines rather than naming the square. Hints are free and unlimited — there is no allowance, no pool, and nothing to spend. A new Hints switch in Settings removes the option entirely for anyone who would rather not be offered it.
- A puzzle solved with help still counts as solved. It adds to your games played and your win rate exactly like any other, but it does not set a best time — a record is a claim about solving unaided. Asking for a step that turns out to be unavailable costs nothing.
- Launch now opens with the GameDrawer mark on a matching native and in-app brand frame, then transitions directly into onboarding or The Drawer without flashing the wrong destination.
- GameDrawer now uses the 9A.2 Video drawer app icon across light, dark, and tinted appearances.
- Nonogram now previews the targeted cell and highlights its row/column hints while the finger is down. Players can slide to correct an adjacent-cell miss before lifting to commit, making 20×20 boards safer in Lives mode.
- The Nonogram grid now uses 85% of its available width instead of 78%, giving every cell a larger physical target—most noticeably on 20×20 puzzles.
- Horizontal Nonogram clues now use explicit centered-dot boundaries (`1·5·11`) so adjacent clues cannot be mistaken for one multi-digit number; the hint rail remains the same size.
- Nonogram clue cross-offs now preserve puzzle information: unique completed run lengths still cross immediately, while repeated values wait for visible progress anchored from either edge.
- Fast Nonogram swipes fill the complete path immediately instead of visibly trailing behind the finger.

## Internal changes
- Added a shared, token-driven assist card and toolbar entry point, persisted
  assist state across supported save formats, and unified assisted-result
  disclosure and record eligibility across time- and score-based games.
- Added deterministic assist-engine and continuation coverage for Nonogram,
  Sudoku, Minesweeper, FreeCell, Five Letter, and assisted record semantics.
- `AppStartupController` gained `reconfigure(cloudSyncEnabled:)`, which rebuilds the `ModelContainer` against a new sync mode in place. `cloudSyncEnabled` changed from a `let` captured at init to a `private(set) var`, and a `containerToken` now keys the destination subtree in `AppEntryRootView` so a swapped container rebuilds the tree instead of leaving `@Query` views bound to the retired `ModelContext`. Both modes open the same on-disk store (D-08 same-store-path), so no local row is created, moved, or deleted — only CloudKit mirroring changes. The controller is injected through a new `\.appStartupController` environment key, matching the existing `AuthStore` seam.
- Deleted `AuthStore.shouldShowRestartPrompt` and the root-level "Quit and reopen to finish iCloud setup" alert in `RootTabView` (D-03/D-04/D-05). Both existed only to work around the sync mode being fixed at launch; with live reconfiguration there is nothing left for the user to do by hand.
- Moved SwiftData container preparation behind an observable startup controller, with delayed progress feedback, debug launch-path seams, and focused state/UI coverage.
- Added regression coverage for swipe activation thresholds, horizontal/vertical path interpolation, row-hint display/accessibility grammar, and nuanced clue cross-off behavior.
- Added a UI regression test that reproduces the post-transfer Keychain/UserDefaults desync (sync flag on, no stored Apple userID) and asserts the account-management rows stay reachable.
- Repointed all repo paths from the dead `~/Desktop/<Repo>` layout to `~/Developer/<Repo>` (WRAPUP.md, CLAUDE.md, `tools/nonogram/finalize.py`). The wrap-up website step was an `&&` chain starting with `cd` into a missing directory, so it short-circuited and no-oped silently; it is now separate statements behind an explicit failure guard.
- Widened the pre-commit token-discipline hook from `Games/` and `Screens/` to also cover `Core/` and `App/`, matching CLAUDE.md §1, which states the no-hardcoded-colors rule with no directory carve-out. Only newly added lines are inspected, so existing code is unaffected. `Core/GameKitClassic.swift`, `Core/GameKind+AccentColor.swift`, and `Core/SurfaceDepth.swift` carry a documented Color-only exemption because they define the raw colors the rest of the app consumes through tokens; the radii and spacing checks still apply to them.
- Collapsed `AGENTS.md` into a git symlink to `CLAUDE.md`, making agent-rule drift structurally impossible. The two files had been hand-maintained mirrors and had already diverged — AGENTS.md still declared "MVP scope: Minesweeper only" after v1.5 shipped with Stack and Snake. Content unique to AGENTS.md and still true was folded into CLAUDE.md first, including a new §0.5 Commands section (CLAUDE.md previously documented no build command at all).
- Added `Core/AppLog.swift`, a central `os.Logger` namespace (app, audio, auth, sync, storage, puzzles, haptics), mirroring the `AppLog` pattern in FitnessTracker. `NonogramLibrary` and `SFXPlayer` now log through it instead of `print()` and inline `Logger(subsystem:category:)` construction; the Nonogram calls also lose their `#if DEBUG` guards, since `os.Logger` is compiled out of the hot path when not collected. Recorded as CLAUDE.md §8.17, with a documented carve-out for the dev-only seeders (`ScreenshotSeeder`, `DummyDataSeeder`, `AppStartupController`) whose output is meant for a human watching Xcode's console.
- Pre-commit hook hardened: added a `print()`/`debugPrint()` check honoring the §8.17 tooling carve-out, added a line-level `// token-exempt: <reason>` escape hatch matching FitnessTracker's hook (a bare `// token-exempt` with no reason does not suppress), widened the Finder-dupe pattern from ` 2.swift` to any ` <n>.swift`, and replaced the filename loop with NUL-delimited iteration — the previous `for f in $staged` word-split on paths containing spaces, which is exactly the Finder-dupe case the first check exists to catch.

## Fixes
- Nonogram talkthrough highlights no longer disappear after the first marked
  square, and each square now communicates the required action without relying
  on color. Five Letter's useful-guess search is bounded so opening help does
  not stall gameplay against the full accepted-word dictionary.
- Undo now survives closing the app. Neither solitaire saved its undo stack, so reopening a game in progress left the button dead — in FreeCell, which keeps unlimited undo while you play, a long deal could lose dozens of reversible moves because you took a phone call. Both games now persist the last 20 moves alongside the saved board. Saves written by earlier versions carry no history and resume exactly as they do today, with undo simply empty.
- Undo now works when you are stuck in Klondike and FreeCell. It required the game to be in play, so it switched itself off the instant the deal died — the one tool that could back you out stopped working at exactly the moment you needed it. Undo now stays available at a dead end and returns the deal to play, which matters most in FreeCell, where deals are near-always winnable so a dead board usually means a recoverable misplay rather than a bad deal.
- Losing deals are no longer recorded before you accept them. Both games wrote the loss the moment the dead end was detected. That was merely premature while undo was disabled; with undo able to revive a deal it would have become a double-count, since the same deal could then also be won. The loss is now held and written when you actually move on — restarting the deal, taking a new one, or leaving the screen — and dropped entirely if you undo back into play. The saved game is kept at a dead end for the same reason, instead of being discarded on the spot.
- Nonogram Free mode now tells you when a line has gone wrong. Like Sudoku, free mode consulted the solution only in the Lives branch, so a wrong fill early on was invisible and the board simply never completed. The game was already detecting the problem and discarding it: the cross-off pass computes whether a line's clues can still be satisfied, and rendered "this line is now impossible" identically to "nothing crossed off yet". A row or column that can no longer match its clues now shows its clue numbers in the danger color, and VoiceOver reads "line no longer matches its clues". Deliberately line-level rather than cell-level: with only filled and empty to choose from, pointing at the wrong cell would hand over the solution, whereas pointing at the line tells you only what a careful re-read of the clue would have. A gap between fills is not treated as an error until you mark it empty, since an unfilled cell means "not decided yet". Lives mode is unchanged — it marks and locks a wrong fill immediately, so it cannot accumulate a contradiction.
- Sudoku Free mode now shows a wrong digit as wrong. It previously accepted any digit silently, so a mistake early on left you solving a board that could never come out, with no signal of any kind — for the rest of the session. Both the mode's own documentation and the comment in the commit path claimed wrong placements showed red; the highlight was never built. User digits that disagree with the solution now render in the danger color and read as "incorrect" to VoiceOver, and clear the moment you fix or erase them. Lives mode is untouched: it rejects wrong values rather than committing them, so it can never hold one. The tradeoff is accepted deliberately — you can now brute-force Free mode by trying digits until nothing is red, but Free mode already has no lives, no failure state, and unlimited erase, and letting someone waste an hour on a dead board is the worse outcome. Lives mode remains the version with stakes.
- Stack and Snake now tell you how the run went when it ends. Both game-over banners shipped with no subtitle at all, and Stack tracked no best score anywhere in the game, so dying said nothing about what you were chasing or whether you had just beaten it — the v1.5 spec asked for a run summary with a personal-best indicator and it was never built. The banner now reads "New best - 24" when the run beat your stored best, or "Score 18 - Best 24" when it did not, with VoiceOver given the same information rather than a reduced version. A first-ever run shows no summary: with nothing stored there is no record to break, and Stack's score floor is 1 because the base block is already placed, so a naive comparison would have congratulated every new player on "New best - 1" the instant they missed.
- Merge now shows your real best score instead of your best since opening the app. `bestScore` was only ever raised by a swipe during the current session, so a fresh launch displayed "Best 0" and then reported whatever you scored next as an all-time best — on the header chip, the Video Mode chips, and the "Best: N" line on the end-state card. It now reads the stored best for the current mode on launch, on mode switch, on save restore, and again after a run is recorded, and takes the higher of stored and live score so a run in progress never appears to lose ground.
- The Five Letter daily puzzle is now the same word for everyone on a given date. Answer selection used `abs(puzzleId.hashValue) % answers.count`, and Swift seeds its hasher per process — so the daily word changed on every relaunch, and no two players or devices were solving the same puzzle. It only looked stable because the first guess writes a save that pins the answer, meaning quitting before guessing silently reshuffled the day. Selection now goes through `StableHash` (FNV-1a/64, specified by constant so the mapping is frozen), with golden-value tests that treat a change to the mapping as a product regression rather than a stale expectation. In-flight saves are unaffected: the save state stores the answer and `restoreState` reads it back, so a puzzle already in progress keeps its word. This also unblocks the Daily challenge slice, whose ship gate requires determinism for the local date.
- Turning on iCloud sync now takes effect immediately instead of asking the user to quit and reopen the app. The container's sync mode was decided once at launch, so signing in only wrote a flag — anyone who dismissed the restart prompt (or simply did not force-quit) kept using a local-only store while their iCloud stats sat untouched. This was the whole first-run restore experience on a new device, not an edge case. Signing out, account deletion, and silent credential revocation now drop the container back to local-only in the same session too, so writes after sign-out no longer reach the account just left.
- Replaced the startup-time SwiftData fatal error with a data-safe retry screen when the persistent container cannot open.
- Removed the cell-edge sample rejection that delayed fast-swipe interpolation.
- Unified tap targeting and swipe-to-fill under one board gesture: short touches commit the previewed cell on lift, while longer axis-locked movement becomes a smear.
- Expanded the grid while retaining the existing hint strips; a broader hint-layout redesign remains intentionally out of scope for this patch.
- Settings → SYNC now keeps Sign out and Delete account reachable whenever iCloud sync is actually running, not only when a Keychain sign-in record exists. The developer-team transfer changes the App ID prefix, which orphans that Keychain record on update while the sync flag survives — previously that combination hid both controls while stats kept syncing.
- A Sign in with Apple credential state of `.notFound` no longer signs the user out. `.revoked` and `.transferred` still do — both are positive server statements, and `.transferred` is what the developer-team transfer produces. An unrecognized future state now also preserves the session. The argument is the asymmetry, not a reproduction: `.notFound` is ambiguous between "no credential exists" and "not visible right now", and only the first reading justifies destroying one. Keeping a stale credential costs nothing here (the user can sign out from Settings, a real `.revoked` resolves it on the next probe, and iCloud sync is gated on `cloudSyncEnabled` rather than on the credential); discarding a valid one silently flips the UI to signed-out.
- A `credentialRevokedNotification` arriving within 5 seconds of a successful sign-in is now ignored, on the reported behavior that Apple posts it on some successful authorizations. Outside that window a revocation is honored unconditionally — revoking access from Settings -> Apple Account must still sign the user out — and `validateOnSceneActive()` still acts on a `.revoked` probe with no grace period, so the guard has a backstop within one scene activation. `AuthStore` takes an injected clock so both sides of the boundary are tested without sleeping.
- **Both of the two entries above are unverified hardening, not reproduced fixes.** Neither behavior was observed in GameKit; both were ported after auditing FitnessTracker's auth path. The one live observation behind them — a `credentialState` probe returning `.revoked` moments after a successful sign-in — came from the FitnessTracker *simulator*, where Sign in with Apple credential state is not trustworthy, and it was a probe result rather than the notification the 5-second window guards. An earlier draft of this log and of commit 28faa4d cited that observation as direct evidence for the notification path; it is not, and that claim is withdrawn here. The `Ignoring credentialRevokedNotification` log line is the instrument: if it never fires on a real device, this guard is inert and should be deleted rather than kept on faith.
- The SYNC status row no longer reports "Synced just now" off a CloudKit `.setup` event. `.setup` only means CloudKit reached the container; no record has moved in either direction, and on a fresh install it fires before any import — so a restore that pulled nothing still read as a healthy one. The row now stays on "Syncing…" until an `.import` or `.export` actually completes. Setup *failures* still surface as "iCloud unavailable". Found while diagnosing the same defect in FitnessTracker's sync pill.

## Risks / notes
- The native launch frame uses a fixed brand background because UIKit renders it before DesignKit and the saved user theme are available; the app crossfades from that frame into the resolved theme.
- The selected icon intentionally uses one unified full-color master across all three iOS appearance slots.
- Build 2 uploaded with warning ITMS-90076 (potential loss of Keychain access): the developer-team transfer moved the App ID prefix from JCWX4BK8GW to ATRCA5V7ZV. The warning is informational and unfixable in the binary — the old prefix cannot be reclaimed. Only the stored Sign in with Apple userID is affected; local stats, the iCloud sync flag, and the CloudKit container are untouched, so sync continues across the update and affected users simply re-sign-in. Apple's transfer_sub user-migration endpoint (TN3159) is not needed here because the userID is not used as a data key.
- Nonogram swipe activation now requires 24–32pt of initial travel, leaving room to correct an adjacent target before touch-up; interpolation still backfills every cell crossed before activation.
