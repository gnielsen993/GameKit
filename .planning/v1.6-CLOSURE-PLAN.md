# v1.6 closure plan

Created 2026-09-08. Owner: Codex. Status: local implementation and verification complete; release checks pending.

Gabe authorized creating and executing this plan after the user audit in
`Docs/audits/v1.6-user-audit-2026-09-08/README.md`. This closes existing 1.6
work directly; it does not reopen or renumber the historical milestone phases.

## Acceptance contract

Help must give a correct, useful next action; retain only valid targets; pause
timed play while being read; and preserve a usable board at small sizes and
large text. Existing games, saves, records and signed-out play must keep working.

## Execution

1. **Hint correctness (F02–F05).** Fix false Nonogram premises, Sudoku value
   application in Notes, stale FreeCell moves, and Five Letter last-turn and
   zero-information probes. Promote reproductions and add mutation edge cases.
   Files: each game's engine/view model and focused unit tests.
2. **Presentation and lifecycle (F01, F06–F10).** Bound coaching without
   collapsing boards; provide scrolling when controls and board cannot fit;
   compose pause reasons; repair first-move help, teaching copy, accessibility,
   scoring disclosure and Word Grid's displayed awarded points.
   Files: Core coach/layout helpers and affected game views/cell components.
3. **Math Crossword feasibility and reuse.** Inspect the partner's Swift
   engine and tests at a pinned commit. Keep reusable logic independent of
   Solvara's purchases, quotas, theme and storage. Verify deterministic generation,
   equation correctness, unique solutions and hints. Record provenance and
   assess the native gameplay integration before changing the game roster.
4. **Integrated verification.** Run app logic and core package suites; rerun
   the audited user journeys on phone, small phone and tablet, Classic plus
   Dracula/Voltage/Lavender, ordinary text plus accessibility XXXL. Exercise
   resume/undo, practice and honest scores. Retain screenshots and exact results.
5. **Release preparation.** Update 1.6 notes, build number and store copy to
   verified scope; update planning status. Prepare website changes and release
   wrap-up only after code and game scope are verified. Keep physical PiP,
   real-device feedback/performance and iCloud checks explicit until exercised.
