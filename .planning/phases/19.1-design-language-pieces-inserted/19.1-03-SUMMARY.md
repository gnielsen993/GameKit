# Phase 19.1 Plan 03: Sudoku Move Feedback Summary

**Sudoku now answers every move: digits pop in, a correctly completed row/column/box ripples out from the placed cell (45ms per step), a wrong Lives move shakes only that cell, the win ripples the board, and a full unit holding a wrong digit is never acknowledged. The A3 per-cell KeyframeAnimator path was used.**

## Accomplishments

- Task 1: `SudokuCompletionWave` (pure) decides what counts as complete (full and equal to the solution digit, givens count) and orders the ripple (Chebyshev distance for a unit, Manhattan for the win, diagonal when there is no origin). `fireCompletionEffects` now uses it; the glow set clears after 1200 ms instead of 800. `SudokuViewModel.swift` was not touched (still 696 lines).
- Task 2: `SudokuCellFeedback.swift` holds the keyframe tracks, pop transition and shake constants. `SudokuCellView` wraps its body in a `KeyframeAnimator` (wave) plus a `keyframeAnimator` (shake), draws a static 22% accent glow only when motion is off, and the old inverted, ungated glow animation is gone. `SudokuBoardView` computes `motion`, the origin (selected cell) and the steps once per body and passes one shared counter (`completionGlowCount &+ winCount`).
- DESIGN.md (on main, merged into 2.0): 10.2 wrong-move/pop notes and new Unit wave and Win wave rows, 10.3 win row, 10.6 completion row, 8.2 milestone row.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Zero-length keyframe timelines blanked the whole board**
- **Found during:** Task 2, reviewing the `lives-wrong-move` screenshot (the first UI run passed on label assertions while the screen showed an empty grid).
- **Issue:** the shake animator on all 81 cells fired on every wrong attempt; cells that were not flashing had a total timeline duration of 0 and rendered blank (no digits, no peer tint) and stayed blank.
- **Fix:** inactive cells now run the same non-zero durations with flat values, in both the shake and the wave tracks. Re-ran with a second screenshot: board and digits render, the wrong cell stays empty, 2 of 3 lives.
- **Files:** SudokuCellFeedback.swift. **Commit:** `b2eb789`.

**2. [Rule 3 - Blocking] `correctCompletedCells` is `@MainActor`**
- `SudokuBoard`/`SudokuCell` are main-actor isolated by the module default, so a `nonisolated` function could not read them. The rest of the enum stays `nonisolated`.

**3. [Process] Tests accompanying wrong-move UI test**: the Lives test leaves two lives lost in the saved game; the full PiecesSudokuTests run followed by `testDeepLargeText` and `testSmallSudokuAndBackgroundTimer` (after one simulator uninstall) passed, so the plan 02 resume hazard did not bite.

**Total deviations:** 2 auto-fixed, 1 process note.
