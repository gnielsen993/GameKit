<objective>
Give the win path the facts the win sheet needs (did this run set a best, and over what), make room in the view model to hold them, and add the DEBUG near-win fixture so the win can be reached in three taps by Gabe and by UI tests.

Purpose: ROADMAP success criterion 2 ("names a personal best when one was set ... Assisted wins still set no record"), D-09, D-13, D-17, and the research landmines: `GameStats.record` returns nothing and its best-time evaluation is private, and `SudokuViewModel.swift` sits exactly at its 696-line ratchet.

Output: `RecordResult` and `GameStats.recordReportingBest`, the DEBUG fixture with its launch argument, the view model split into `+TestSeam` and `+Outcome`, `SudokuViewModel.lastWinRecord`, a tightened size baseline, and tests. The win sheet that shows the badge is plan 05.

Deviation from RESEARCH.md, with evidence: research proposed making the existing `record(...)` return a `@discardableResult RecordResult`. A typecheck run during planning showed `try? s?.record()` on a non-Void `@discardableResult` function still emits "result of 'try?' is unused", and ten call sites in other games use exactly that form. So the existing signature stays as a Void forwarder and the result comes from a new `recordReportingBest(...)`; the rule still lives in one place.
</objective>
