# GameDrawer v2.0 — Product Plan & Roadmap

**Created:** 2026-07-07

**Revised after roadmap audit:** 2026-07-12

**Status:** Approved direction — release slices still require normal discuss/plan gates

**Owner:** solo (Gabriel)

> This document replaces the original Bands A–E backlog with independently
> shippable product slices. The goal is not maximum engagement at any cost. The
> goal is a friendlier identity, faster access to the games a person values, and
> honest reasons to return without weakening GameDrawer's calm character.

---

## 1. Product thesis

GameDrawer should become a **calm, personal game home** rather than a flat
launcher. It should guide a new user toward a good first action while letting a
returning user jump directly into a favorite or unfinished game.

The existing product identity is not discarded. The current direct-access grid
becomes **Library**: the permanent, low-pressure, complete view of every game.
The new **Home** is the living layer above it: Pinned, Continue Playing, one
timely recommendation, and—once it exists—Daily.

**Target feeling:** "My small game collection, ready when I am."

**Watch Mode remains the differentiator**, but it is a capability inside the
product rather than the only reason the product exists.

---

## 2. Current state and diagnosed gap

**Games (10):** Minesweeper · Merge · Nonogram · Sudoku · Klondike ·
FreeCell · FiveLetter · WordGrid · Stack · Snake.

**Strong foundations already shipped:**

- Video Mode with six PiP zones; eight games adopt it and two are deliberate
  exemptions.
- Save-state for all eight non-arcade games.
- Shared arcade substrate for Stack and Snake.
- Settings, themes, haptics, SFX, optional iCloud/SIWA, stats, and onboarding.
- Polished game screens with consistent DesignKit styling.

**The gap is product hierarchy, not game count:**

- Home gives every game equal weight and offers no preferred next action.
- Saved games exist but are buried.
- Users cannot keep chosen game/mode shortcuts permanently on Home.
- Onboarding configures the app before explaining why it is useful.
- Stats report activity but do little to tell a story of progress.
- There is no calm, finite reason to return on another day.

The app already has enough games to justify improving discovery before adding
more. New roster work is **Later**, not a dependency of 2.0.

---

## 3. Product principles

1. **Guide without coercing.** Recommendations may reduce choice; they must not
   create anxiety, punishment, or manufactured urgency.
2. **User choice outranks recency.** Pinned shortcuts are user-curated and
   permanent. Continue Playing is automatic and temporary.
3. **The complete Library is always one tap away.** No user must engage with
   Daily, recommendations, or personalization to reach a game.
4. **Missing a day costs nothing.** Daily is an invitation, not an obligation.
5. **Assists are kind, optional, and never currency.** Assistance is disclosed
   gently and never sold per use.
6. **Polish before quantity.** A new game must clear the main-library quality
   bar before it can compete for Home placement.
7. **Monetize value, not interruption.** Ads and paid entitlements remain
   decision gates. Neither is required for the identity release.
8. **One implementation, multiple discovery surfaces.** Test game-specific App
   Store product pages before building a standalone app.

## 4. Information architecture

### 4.1 Home — guided and personal

Home is sectioned and scrollable. Sections appear only when they contain real,
actionable content; never ship a nonfunctional Daily placeholder.

Recommended order:

1. **Pinned** — permanent user-selected game or mode shortcuts.
2. **Continue Playing** — resumable save states, newest first.
3. **Today** — one Daily challenge, only after Daily ships.
4. **Featured** — one primary recommendation, not a wall of equal cards.
5. **Best While Watching** — a small curated Video Mode row.
6. **Recently Played** — optional; omit if it substantially duplicates Pinned
   or Continue Playing.
7. **Library entry point** — clear access to all games.

Empty sections collapse. A first-time user sees Featured, Best While Watching,
and Library—not blank Pinned or Continue Playing cards.

### 4.2 Pinned — permanent jump-in shortcuts

Pinned is the answer to "I know what I play; remove the clutter."

**Behavior contract:**

- A user can pin a **game** or, when meaningful, a specific **mode/difficulty**.
- Examples: `Sudoku · Medium`, `Merge · Infinite`, `Minesweeper · Hard`, or
  simply `Snake`.
- A pinned item stays on Home until the user unpins or reorders it.
- Tapping a mode-aware pin deep-links directly into that configuration when it
  is safe to do so; otherwise it opens the game's mode picker.
- If that game has an active save, the shortcut clearly offers Resume versus
  New Game rather than silently destroying progress.
- Initial release target: up to six pins, user-reorderable. Do not add folders
  until real use proves six is insufficient.
- Pin/unpin is available from the Library game's detail surface and by
  long-press/context menu where discoverable.
- The Pinned section can be hidden only by removing all pins. It is not
  algorithmically reordered.
- Persist the small ordered shortcut shape locally; include it in the existing
  versioned export/import format. Cloud sync can follow the established
  preference-sync policy rather than blocking the first release.
- Every pin has an accessibility label that includes game, mode, and action.

**Pinned is not:**

- Continue Playing (automatic save-state list).
- Recently Played (automatic history).
- A separate "Basic Mode" or alternate app identity.
- A promise that bypasses an unfinished game's resume/new-game decision.

### 4.3 Continue Playing — automatic and temporary

- Derived from existing save states; do not introduce a second source of truth.
- Shows only genuinely resumable sessions.
- Ordered by most recently saved.
- Removing a Continue card from Home does not delete game data.
- Completing, resetting, or abandoning the saved game removes the card.
- Empty state is explicit in the full Library/detail context, but the empty Home
  section collapses to avoid clutter.

### 4.4 Library — the current identity preserved

- The current all-games grid/drawer evolves into Library rather than being
  deleted.
- It remains deterministic, complete, and free of engagement ranking.
- Users may choose `Home` or `Library` as their default landing destination in
  Settings if testing shows meaningful demand. Do not build two separate
  navigation systems.
- As the roster grows, add categories/search only when scanning becomes a
  demonstrated problem.

## 5. Release roadmap — ship the smallest coherent part first

Version labels are earned at ship time. A completed slice may ship as a 1.x;
the first bundle that genuinely changes the public identity claims 2.0. Phase
numbers remain append-only from Phase 18 regardless of marketing version.

### NOW — Release Slice 1: Personal Home foundation

**Outcome:** returning users can reach what matters immediately, while new users
receive one understandable recommendation.

**Must ship:**

- Sketch and approve Home + Library navigation before production UI work.
- Introduce the sectioned Home shell.
- Preserve the existing grid as Library.
- Ship Pinned with game/mode shortcuts, persistence, reorder, and direct routing.
- Ship Continue Playing from existing save states.
- Ship one Featured card and a small Best While Watching row.
- Remove Upcoming from prime Home placement.
- Collapse empty sections; verify first-run and returning-user states.
- Review on Classic and one Loud/Moody preset, smallest supported iPhone, and
  accessibility text sizes.

**Explicitly not in this slice:** Daily, streaks, assists, new games, ads,
StoreKit, full rebrand, or default-theme replacement.

**Candidate branch set:**

- `feature/home-activity-foundation`
- `feature/home-pinned`
- `feature/home-continue-playing`
- `experiment/home-guided`

Each branches from `main`. Infrastructure may land first; the experimental Home
branch consumes it. Do not maintain a long-running catch-all `v2` branch.

**Ship gate:** a nontechnical tester can (1) resume a game, (2) pin a preferred
mode, and (3) reach the complete Library without explanation.

### NOW/NEXT — Release Slice 2: Value-first onboarding

**Outcome:** the first 30 seconds explain the product before requesting setup.

**Scope:**

- Lead with the calm collection and fast jump-in value.
- Demonstrate Watch Mode in one concise beat.
- Let the user choose or skip an initial pin; do not require preference work.
- Move theme and optional sign-in after the pitch or into Settings.
- Never gate gameplay on onboarding completion, sign-in, or a purchase.

**Candidate branch:** `feature/onboarding-value-pitch`

**Ship gate:** after the flow, a tester can explain what makes GameDrawer
different and knows how to start a game.

### NEXT — Release Slice 3: One good reason to return

**Outcome:** a calm, finite Daily challenge appears on Home.

**Scope:**

- Choose one deterministic puzzle game for the first vertical slice; current
  preference is FiveLetter or Sudoku.
- Date-seeded challenge and local completion record.
- Today card shows the game and approximate commitment without countdown
  pressure.
- Completion history may show participation; missing a day has no loss state,
  broken-streak copy, or recovery purchase.
- No notifications in the first release.
- No generalized cross-game Daily engine until a second game proves the common
  contract.
- No cross-game streak requirement. Consider a neutral completion calendar or
  total days played before a consecutive-day streak.

**Candidate branch:** `feature/daily-first-game`

**Ship gate:** the challenge is deterministic for the local date, survives
relaunch, and tomorrow's challenge cannot invalidate today's completion.

### NEXT — Release Slice 4: Be Kind pilots

**Outcome:** stuck players can continue without feeling punished.

**Scope:**

- Define shared product language and the persistence/stat disclosure shape.
- Implement assists game-by-game; do not begin with a universal Assist engine.
- Pilot on two games with low-risk semantics, such as Sudoku hint/reveal and a
  reversible undo in a deterministic game.
- Record completion normally with gentle copy such as "Solved with 1 hint."
- Assists remain free and respect haptics, animation, SFX, and Reduce Motion.
- Purist users can disable assist affordances.
- Do not change FreeCell's rules by granting an additional free cell; prefer a
  move hint or undo.

**Candidate branches:**

- `feature/assist-language`
- `feature/assist-sudoku`
- `feature/assist-second-pilot`

**Ship gate:** assisted and unassisted completion are both dignified, clearly
represented, and never monetized per use.

### IDENTITY GATE — GameDrawer 2.0

**Outcome:** the app is publicly re-presented as a calm, personal game home.

2.0 should bundle the proven identity work, not every later roadmap item:

- Guided Home + permanent Pinned shortcuts.
- Continue Playing.
- Library preservation.
- Value-first onboarding.
- One proven Daily experience if it is ready and good; Daily is desirable but
  not allowed to delay an otherwise complete identity release indefinitely.
- Final positioning, App Store screenshots/copy, website, and brand treatment.
- A default-palette change only if first-impression testing shows the palette,
  rather than the old hierarchy, is still a material problem.

**Not required for 2.0:** new games, every-game assists, ads, subscription,
Game Center, standalone apps, or Labs.

**Candidate branch:** `release/v2-identity` created only for final integration
after its component branches are verified. It is not an ongoing development
branch.

### LATER — Monetization decision and implementation

Ads and paid access are options under review, not presumed roadmap outcomes.
They conflict with current product constraints and require an ADR plus explicit
updates to AGENTS.md and CLAUDE.md before implementation.

If ads are approved:

- Existing users should be considered for permanent grandfathered ad-free
  status.
- Prefer a one-time **Remove Ads** purchase.
- Do not place ads during gameplay, beside a board, on loss/win treatments, or
  inside assists.
- Never make hints, undo, second chances, or Daily recovery into rewarded-ad
  currency.
- A subscription should exist only if it offers continuing value beyond static
  ad removal: an expanding premium library, meaningful ongoing content, or
  service-like benefits.
- Consider both lifetime and subscription options if a Plus tier eventually
  has sufficient ongoing value.

If paid Video Mode is approved, StoreKit entitlement infrastructure, offer
presentation, and the public identity release remain separate branches and ship
decisions.

**Candidate branches after the decision gate:**

- `feature/storekit-entitlements`
- `experiment/monetization-offer`
- `feature/ad-integration`

### LATER — Roster expansion

The ten-game library is already sufficient for 2.0. Add a game when it creates
a distinct acquisition, retention, or Watch Mode advantage—not to increase the
count.

Current candidates:

| Candidate | Strategic reason | Current disposition |
|---|---|---|
| Color/Ball Sort | Strongest pure Watch Mode fit | First niche-proof candidate |
| Block Puzzle | Strong general-market/search fit | First broad-market candidate |
| Mahjong-lite/Tile Match | Familiar casual depth | Later |
| Flow Connect | Strong grid/Video Mode leverage | Later |
| Parking Jam/Unblock | Familiar turn-based puzzle | Later |

Do not build Labs until at least one real experiment needs to ship hidden.

## 6. App Store discovery before standalone apps

The portfolio strategy is **hub first, focused surfaces second, standalone only
when earned**.

### 6.1 Product-page experiment

Before creating a separate bundle ID:

1. Create game-specific App Store custom product pages for the strongest search
   candidates: Solitaire, Sudoku, Minesweeper, and optionally Nonogram.
2. Give each page focused screenshots, preview video, promotional text, and
   relevant keyword assignment. The page must truthfully show the GameDrawer
   experience while leading with that game.
3. Add an iOS 18+ deep link from each product page into the highlighted game's
   route. Older systems fall back to Home with the highlighted game visible.
4. Use a dedicated campaign/link per page so App Store Connect can compare
   impressions, conversion, and downloads.
5. Separately run product-page optimization on the default listing to test the
   hub's icon/screenshots/positioning.
6. Observe conversion and in-app game selection before approving a standalone.

Apple currently permits up to 70 custom product pages and allows approved pages
to use distinct screenshots, promotional text, keywords, and supported deep
links. Reference:
<https://developer.apple.com/help/app-store-connect/create-custom-product-pages/configure-multiple-product-page-versions/>

### 6.2 Standalone approval gate

A standalone is approved only when all are true:

- Search demand or product-page conversion indicates a focused acquisition
  opportunity.
- The game has enough depth for a game-specific product—not merely GameDrawer
  opening directly into the same screen.
- The standalone has distinct onboarding, Home, stats/progression, metadata,
  and at least one meaningful game-specific feature or content layer.
- Shared DesignKit/engine code can be reused without coupling release safety.
- Data ownership, cloud containers, purchases, and cross-promotion behavior are
  decided before implementation.
- The proposal is reviewed against App Review Guideline 4.3. Do not submit a
  family of thin, template-like clones under separate bundle IDs.

Strongest initial candidates:

1. Solitaire product: Klondike + FreeCell, richer variants, focused Daily and
   card-game stats.
2. Sudoku: focused Daily, difficulty/progression, assists, and puzzle history.
3. Nonogram: puzzle packs/history and a distinct content proposition.
4. Minesweeper: only if it gains enough modes/challenges to differentiate in a
   saturated category.

Stack and Snake remain hub games unless usage reveals standalone demand.

### 6.3 Relationship between hub and standalone

- GameDrawer is the canonical breadth product and the home of Watch Mode,
  themes, Pinned shortcuts, and cross-game Daily discovery.
- A standalone is the canonical depth product for one game family.
- Cross-promotion is quiet and contextual; never interrupt gameplay.
- Do not promise automatic entitlement or save sharing until Apple account,
  CloudKit container, App Group, and StoreKit implications are designed and
  tested.

## 7. Quality gates

### Home/identity gate

- First-time, empty, partially populated, and heavily populated states exist.
- Pinned and Continue Playing remain visually and semantically distinct.
- Direct Library access never disappears.
- Classic and one Loud/Moody preset pass.
- Smallest supported iPhone and accessibility text pass.
- Cold start is not materially regressed by reading save-state summaries.

### Main-library game gate

Before a new game is visible in Library it must:

- work in Video Mode or have a deliberate documented exemption,
- have save/resume where meaningful,
- have clean empty/error/win/loss states,
- respect feedback and accessibility settings,
- pass at least Classic plus one Loud/Moody visual audit,
- be understandable within five seconds,
- have a clear reason to replay,
- and feel at least as complete as the existing featured games.

### Standalone gate

In addition to the game gate, it must pass §6.2 and demonstrate a distinct
product proposition. Code reuse alone is not a product reason.

## 9. Open decisions

1. Does Home replace the current root while Library becomes a tab/destination,
   or does a lightweight segmented control switch between them? Sketch before
   deciding.
2. Should a pin launch a chosen mode immediately or open the game detail panel
   with that mode preselected? Use resume/new-game safety as the tiebreaker.
3. Should users be able to set Library as their default landing destination at
   first release, or add that only if requested during testing?
4. Which game earns the first Daily vertical slice?
5. Is the identity still explicitly "Watch Mode hub," or the broader "personal
   game home" with Watch Mode as its signature capability?
6. Does monetization remain purchase-based, become restrained ad-supported with
   permanent ad removal, or later support a Plus subscription with genuine
   continuing value?
7. Which product-page experiment runs first: Solitaire for search breadth or
   Sudoku for a clearer focused Daily proposition?

---

## 10. Recommended execution order

`Home/Library sketch → Pinned + Continue contracts → guided Home → onboarding →
first Daily → Assist pilots → 2.0 identity integration → product-page tests →
monetization decision → roster/standalone bets`

This order improves the product users already have before creating more content
or business-model complexity. Every early slice can ship independently, and no
unproven subscription, ad system, new game, or standalone can hold 2.0 hostage.
